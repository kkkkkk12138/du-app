## 第一阶段 发布政策页面

前提：

- GitHub 账号 `kkkkkk12138`。
- 新建公开仓库 `du-legal`。
- 政策中的运营者姓名和邮箱已填写。

操作：

1. 创建公开仓库 `kkkkkk12138/du-legal`。
2. 上传主页、隐私政策、服务条款和支持页面。
3. 在仓库“Settings > Pages”中选择 GitHub Actions 或 `main` 分支。
4. 等待 Pages 首次部署完成。
5. 在未登录浏览器中分别打开：
   - `https://kkkkkk12138.github.io/du-legal/`
   - `https://kkkkkk12138.github.io/du-legal/privacy/`
   - `https://kkkkkk12138.github.io/du-legal/terms/`
   - `https://kkkkkk12138.github.io/du-legal/support/`
6. 检查页面无需登录、HTTPS 有效、移动端可读、没有身份证号或手机号。
7. 将 URL 填入 App Store、Google Play 和国内商店材料。

验收结果：四个 URL 在匿名窗口返回 200，页面内容与 App 内政策一致。

常见问题：

- 返回 404：检查 Pages 发布源和目录结构。
- 页面仍显示占位符：先停止申报，补齐运营者和邮箱后重新部署。
- GitHub Pages 在目标网络不可稳定访问：迁移到本人持有并备案的域名。

## 第二阶段 申请 APP 备案

前提：

- 本人身份证、实名手机号和真实住址。
- 公开政策页面。
- 支持个人 APP 备案的接入服务商或应用分发平台。
- 若接入商要求，准备本人域名和中国大陆网络资源。

操作：

1. 阅读 [APP 备案申报材料](APP_FILING_APPLICATION.md)。
2. 选择接入商，在其备案控制台完成个人实名认证。
3. 新建 APP 备案，主体性质选择“个人”。
4. 填写“渡”、`com.duapp`、版本 1.0.1 和服务内容。
5. 填写真实域名、IP 或接入资源；没有真实资源时咨询接入商，不编造。
6. 上传接入商要求的身份证明、承诺书、政策链接和应用信息。
7. 由本人完成人脸核验和短信核验。
8. 提交初审。
9. 根据退回意见修改同一申请，不重复创建相互冲突的主体。
10. 收到管局短信时，在规定时间内完成核验。
11. 审核通过后保存备案编号和通过日期。
12. 在 App“关于渡”、公开政策页面和各商店后台展示备案编号。

验收结果：备案系统可以按备案编号查询到“渡”，主体、包名和实际提交一致。

常见问题：

- 类目要求前置审批：当前产品不要选择新闻、出版、教育、影视、宗教等需要主管部门文件的类目。
- 包名不一致：所有商店和备案统一使用 `com.duapp`。
- 政策主体不一致：政策运营者、备案主办者和商店开发者必须是同一人。

## 第三阶段 申请软件著作权

前提：

- 中国版权保护中心个人账号已实名认证。
- 软件全称确定为“渡个人时光记录软件”。
- 版本号确定为 V1.0。
- 个人独立开发和权属表述真实。

操作：

1. 阅读 [软著申报材料](SOFTWARE_COPYRIGHT_APPLICATION.md)。
2. 运行：

   ```sh
   bash scripts/generate-software-copyright-source.sh
   ```

3. 检查生成的源程序没有密码、密钥、真实用户数据或第三方依赖源码。
4. 将源程序排为纵向 PDF，等宽字体，每页 50 行，页眉写“渡个人时光记录软件 V1.0”。
5. 将 [用户操作手册](SOFTWARE_USER_MANUAL.md) 排为纵向 PDF，页眉和版本与申请表一致。
6. 登录 `https://www.ccopyright.com.cn/`。
7. 选择计算机软件著作权登记申请。
8. 按预填表录入软件、开发环境、运行环境、功能和技术特点。
9. 上传源程序 PDF、用户手册 PDF和身份证明。
10. 下载系统生成的确认签章页。
11. 保持原格式打印，由本人签字，再扫描上传 PDF。
12. 提交申请并保存流水号。
13. 每周查看用户中心站内信；收到补正后在 30 日内处理。
14. 审查完成后下载电子证书并核验电子签章。

验收结果：获得可验证的电子证书，软件名称、版本和著作权人无误。

常见问题：

- 页眉版本不一致：申请表、源程序和手册统一使用 V1.0。
- 软件全称过于通用：始终使用“渡个人时光记录软件”。
- 个人权属不真实：若属于职务、委托或合作开发，应按真实权属补证明。

## 第四阶段 生成正式候选包

前提：

- `main` 已包含发布源码。
- Git 标签为 `v1.0.1`。
- 生产 JKS 和密码文件在本地私密目录。

操作：

1. 执行 TypeScript、ESLint 和 Jest：

   ```sh
   npx tsc --noEmit
   npx eslint . --max-warnings=0
   npm test -- --runInBand
   ```

2. 构建 APK 与 AAB：

   ```sh
   cd android
   ./gradlew :app:assembleRelease :app:bundleRelease
   ```

3. 核对：
   - 包名 `com.duapp`
   - `versionName=1.0.1`
   - `versionCode=2`
   - `minSdk=26`
   - `targetSdk=36`
4. 使用 `apksigner verify --print-certs` 核对生产证书。
5. 计算 APK 和 AAB 的 SHA-256。
6. 将最终文件复制到独立本地发布目录。
7. 不把 APK、AAB、JKS、密码或 `keystore.properties` 提交 GitHub。

验收结果：签名、包名、版本和摘要均记录在发布材料包。

## 第五阶段 真机回归

前提：

- 至少一台 Android 10 及以上真机。
- 最好再准备一台 Android 8/9 设备验证旧版相册权限。
- 使用无私人数据的测试账号环境。

按以下顺序测试：

1. 全新安装、隐私同意和首次示例。
2. 中文、英文和混合输入。
3. 自动定位、手动地点和城市统计。
4. 拍照、相册、录音、播放和手书。
5. 日迹保存、详情、存为图片和删除。
6. 未来信年月日时分选择、通知和拆信。
7. 念想、副本、书架和散页的新增、查看、修改与删除。
8. 头像、昵称、提醒和生物识别。
9. 完整备份、卸载重装和恢复。
10. 从上一候选版本覆盖安装，核对数据库迁移。
11. 断网运行和拒绝各项权限。
12. 冷启动、后台恢复和系统重启后的提醒。

验收结果：没有崩溃、阻断操作、数据丢失、声明外联网或无法删除的内容。

## 第六阶段 制作商店素材

1. 在无私人数据的正式 Release 包中创建一组完整示例。
2. 截取日迹、落笔、未来信、远方、书架、散页和数据隐私页面。
3. 不展示真实姓名、手机号、精确地址、照片、录音波形或备份路径。
4. 使用 `assets/store/android/app-icon-1024.png` 作为商店图标母版。
5. 使用 `assets/store/android/feature-graphic-1024x500.png` 作为需要宣传图的平台素材。
6. 按各商店当日尺寸要求裁切，不拉伸图标。
7. 文案使用 [RELEASE_SUBMISSION_PACK.md](RELEASE_SUBMISSION_PACK.md) 中的统一版本。

验收结果：素材与真实功能一致，不宣称账号同步、云端备份或尚未上线的收费能力。

## 第七阶段 建立商店应用

每家商店独立执行：

1. 注册个人开发者并完成实名认证。
2. 确认生活/实用工具类目接受个人主体。
3. 创建新应用，填写名称“渡”和包名 `com.duapp`。
4. 上传同一个生产签名 APK。
5. 填写版本 1.0.1 和统一更新说明。
6. 上传图标、截图和宣传图。
7. 填写隐私政策、服务条款和支持 URL。
8. 填写 APP 备案编号。
9. 上传软著电子证书或平台接受的替代权利证明。
10. 填写权限用途、个人信息处理和第三方 SDK 清单。
11. 声明无广告、无账号登录、无云同步、无第三方统计。
12. 填写审核操作路径。
13. 提交审核并保存工单号。

不要为不同商店生成行为不同的渠道包，不要更换包名或签名。

## 第八阶段 处理审核反馈

1. 将每条驳回意见原文保存到发布记录。
2. 区分代码问题、材料问题、主体资格问题和政策变更。
3. 代码变化必须增加 `versionCode`。
4. 只修改文案或截图时，按平台规则决定是否重传 APK。
5. 权限与隐私声明冲突时，以最终 APK 实际行为为准修改政策和后台问卷。
6. 不使用虚假截图、虚假备案号或虚假证书绕过审核。
7. 审核通过后先小范围发布，检查下载、安装、首次启动和更新。

## 发布前停止条件

出现以下任一情况时停止提交：

- 政策页仍含占位符或无法匿名访问。
- APP 备案编号尚未取得但商店明确要求。
- 软著主体、软件名或版本与商店不一致。
- APK 包名、签名或版本与材料不一致。
- 真机无法输入中文、无法恢复备份或存在启动崩溃。
- 应用声明云同步，但当前版本没有服务端同步。
- 商店要求公司主体或前置许可，而当前个人主体不符合。
