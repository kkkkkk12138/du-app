# 渡账号同步、媒体计费与支付设计

状态：方案已确认，待完整实现
日期：2026-09-02  
适用分支：`feat/account-sync-media-billing`  
历史基线：`pre-account-sync-2026-09-02`（`2b4d693`）

## 决策摘要

本设计延续 `docs/ACCOUNT_SYNC_PLAN.md` 的本地优先、可选账号和端到端加密
方向，并替代其中未最终确定的产品表达、媒体额度、收费方式和付费触发规则。

1. 不注册也能使用全部本地创作能力。
2. 首次说明直接写明：
   `不注册使用，内容只保存在这台设备。更换手机后，旧内容不会出现在新设备；删除应用或设备损坏后，内容无法恢复。`
3. 注册后，文字和结构化数据自动同步且长期免费。
4. 注册账号包含 500 MB 免费媒体空间。
5. 免费空间用完前不弹容量营销提示；用户可在账号页主动查看用量。
6. 空间用完后仍可写纯文字；新照片、录音和手书需要媒体额度。
7. 创作过程不插入付款。整篇日迹或信件完成并点击保存或寄出时，统一结算全部媒体。
8. 只有媒体完成客户端加密、上传并得到服务端确认后才扣除额度。
9. 收费采用单次、次数包和可选月度方案并存，不强制订阅。
10. 应用内数字服务只使用对应应用商店的合规支付渠道。
11. “请 DU 喝杯茶”作为独立消耗型内购，不增加额度、不解锁功能。
12. 账号、同步、恢复、删除和支付全部验收前，不宣称这些能力已经可用。

## 后端边界

本设计将正式技术路线固定为：

- CloudBase：账号认证、云函数、结构化密文和同步游标。
- 腾讯云 COS：加密后的照片、录音、手书、头像和封面对象。
- 开发、预发布和生产环境严格隔离。
- 服务端验单、额度账本、同步协议和注销清理由云函数承载。
- 不租单台 VPS，不让应用客户端直接持有数据库、COS 或支付服务密钥。

这项决策替代 `docs/ACCOUNT_SYNC_PLAN.md` 中“优先评估 LeanCloud”的旧候选
路线。旧文档继续作为同步协议背景，不再作为云服务选型依据。

### 云服务选型复核

2026-09-03 重新比较 CloudBase、阿里云 Serverless、自建 VPS、Supabase、
Firebase、CloudKit、Cloudflare R2 和 LeanCloud 后，最终确认使用：

```text
CloudBase：账号、密文索引、同步游标、云函数、额度账本、服务端验单
腾讯云 COS：端到端加密后的照片、录音、手书、头像和封面
```

不采用“全部媒体存入 CloudBase 套餐容量”的方案。CloudBase 个人版容量同时
覆盖数据库和云存储，不适合承载持续增长的媒体库；媒体从第一版开始独立存入
COS，避免后续再做大规模对象迁移。

选择该组合的原因：

- 中国大陆 iOS 与 Android 网络可用性优先，避免把核心同步链路放在境外服务。
- CloudBase 已提供账号认证、云函数、数据库、权限和监控，个人开发者不需要
  维护服务器操作系统、数据库实例、证书、补丁和高可用集群。
- CloudBase JavaScript SDK 支持 React Native 通用 JavaScript 运行环境。
- CloudBase 负责低容量结构化密文，COS 按实际媒体使用量计费，固定成本和
  变动成本可以分开控制。
- 服务端只接触密文、校验值和必要账务元数据，云厂商不能直接读取日记正文
  和媒体内容。
- 同一腾讯云地域内的云函数与 COS 交互可以减少跨地域链路和不必要流量。

未采用的主要方案：

- LeanCloud：长期服务连续性不满足新项目要求。
- Firebase、Supabase、Cloudflare R2：不作为中国大陆核心同步链路，避免
  跨境网络可用性和合规不确定性；Supabase 正式环境还有较高固定月费。
- CloudKit：只适合 Apple 生态，无法覆盖 Android。
- 自建 VPS：表面租用价格低，但数据库备份、安全更新、故障恢复和监控都由
  个人承担，不符合本项目低维护目标。
- 阿里云函数计算 + OSS：技术上可行，作为迁移备选保留；但账号、权限、
  数据库和函数需要组合更多独立产品，首版集成与运维成本高于 CloudBase。

### 成本与扩容策略

- 开发阶段先使用 CloudBase 免费体验环境，不提前购买服务器。
- 正式发布前升级到满足账号、云函数和数据库能力的最低付费套餐；截至
  2026-09-03，个人版页面价格为 19.9 元/月，实际采购以控制台价格为准。
- “每个注册账号 500 MB 免费媒体空间”是产品额度上限，不是预留 500 MB
  物理空间。COS 只按用户实际上传量占用和计费。
- 图片必须压缩，录音必须转为 48–64 kbps AAC/M4A，媒体按内容哈希去重。
- 新设备优先恢复结构化记录和缩略信息，媒体按需下载并使用本地缓存，控制
  下行流量。
- 开启 20 元、50 元和 100 元分级费用告警；生产环境默认设置费用上限和
  异常调用告警。
- 当用户量和媒体量增长后，优先购买 COS 存储与流量资源包，不直接升级昂贵
  的 CloudBase 企业套餐。

### 可迁移性边界

业务层不得直接依赖腾讯云 SDK，必须通过以下接口访问外部能力：

```text
AuthProvider
SyncBackend
ObjectStorage
BillingVerifier
```

CloudBase 和 COS 仅作为首个适配器。同步协议、密文格式、对象键规则、额度
流水和导出格式由 DU 自己定义，确保未来可以将对象存储迁移到 OSS，或将账号
与同步后端迁移到其他服务，而不重写日迹、信件和本地数据库业务。

### 外部资源准备

开始真实联调前，项目所有者需要在腾讯云完成：

1. 实名认证腾讯云账号。
2. 创建上海地域的 CloudBase 免费体验环境。
3. 创建同地域、禁止公开读写的 COS 测试桶。
4. 开启费用告警。
5. 向开发配置提供 CloudBase 环境 ID、COS 地域和桶名称。

SecretId、SecretKey、商店密钥和签名文件不得写入聊天、源码或 Git。需要授权
时只在本机安全环境或 CI Secret 中完成。

## 用户可见概念

产品只使用用户已经理解的词：

- 注册
- 登录
- 同步
- 媒体空间
- 媒体额度
- 恢复凭证

不引入“云端保护”“找回我的记录”等概念。新设备只提供注册和登录，用户
登录同一账号并完成旧设备批准或恢复凭证验证后自动同步。

加密密钥是内部实现，不向用户展示。恢复凭证是新设备在没有可信旧设备时
解锁已同步内容的必要备用路径。

登录方式按邮箱/手机号、Apple、微信顺序交付。所有方式必须关联到同一个
CloudBase UID。Apple 或微信首次授权若没有绑定记录，不静默创建第二账号；
用户必须验证已有邮箱或手机号后完成关联。

## 注册与未注册

### 未注册

- 所有内容写入 WatermelonDB 和应用私有附件目录。
- 文字、照片、录音和手书均可正常使用。
- 换机不会自动出现旧内容。
- 删除应用、清除数据或设备损坏后，未备份内容无法恢复。
- 现有完整备份、校验、恢复和失败回滚继续保留。

Profile 展示：

```text
未注册
内容只保存在本机
```

### 已注册

- 本机仍是主数据库，离线可写。
- 文字、标签、地点、信件、念想、副本、书页和散页等结构化数据免费同步。
- 照片、录音、手书、头像和封面共享 500 MB 免费空间。
- 新设备登录同一账号并解锁主密钥后自动恢复。
- 正常保存不显示“已保存在本机”等额外反馈。

账号页至少展示：

```text
账号
最近同步
照片与录音空间
等待同步项目
同步网络设置
恢复凭证
退出登录
注销账号
```

## 端到端加密与恢复

### 内部密钥

- 每个账号在设备端生成 256 位主密钥。
- 文字字段和媒体使用 AES-256-GCM，每个对象使用独立随机 nonce。
- 主密钥保存在 Keychain 或 Android Keystore。
- 登录身份与加密身份分离。邮箱、手机号、Apple、微信只用于证明账号归属。
- 主密钥至少由 12 词恢复凭证派生的包装密钥保护。
- 新设备可以通过可信旧设备的设备密钥交换获得主密钥包装结果。
- 邮箱或手机号密码不得成为唯一恢复路径，第三方登录令牌不得用于派生主密钥。
- 服务端只保存密文、盐、被包装的主密钥、设备公钥、同步元数据和校验值。
- 服务端不保存恢复凭证、包装密钥或明文主密钥。

### 正常登录

用户可以通过邮箱验证码、手机号验证码、Apple 或微信登录同一账号。登录成功
只证明账号归属；如果本机没有已解锁主密钥，账号进入“已登录，等待解锁”
状态，可以查看账号信息，但不能下载、上传或展示历史密文。

新设备必须由仍然登录且持有主密钥的可信旧设备批准，或输入恢复凭证。完成
解锁后才开始同步。登录渠道的密码重置、短信换号或第三方账号重新授权都不能
绕过这一步。

### 恢复凭证

固定入口：

```text
我 → 账号 → 恢复凭证
```

支持保存到系统密码管理器、导出恢复文件、显示 12 个恢复词和重新生成。
查看或重新生成前必须通过生物识别或设备密码。不提供“保存到相册”。

新设备解锁时：

1. 优先由仍然登录的旧设备批准新设备。
2. 没有旧设备时使用恢复凭证。
3. 两者都没有时仍可重新验证账号身份，但历史密文无法解密。

进入第三种路径前必须明确说明无法恢复历史内容的后果。

## 媒体计费

### 免费范围

- 纯文字与结构化数据免费同步。
- 注册账号包含 500 MB 媒体空间。
- 免费空间用完前不主动弹出 80% 等营销提示。
- 账号页始终允许用户主动查看用量和规则。

### 媒体额度

| 商品 | 价格 | 类型 |
| --- | ---: | --- |
| 1 次 | ¥1 | 消耗型应用内购买 |
| 5 次 | ¥4 | 消耗型应用内购买 |
| 10 次 | ¥6 | 消耗型应用内购买 |
| 20 次 | ¥10 | 消耗型应用内购买 |
| 每月 20 次 | ¥8/月 | 自动续期订阅 |
| 每月 60 次 | ¥18/月 | 自动续期订阅 |

最终价格必须由应用商店返回，客户端不得写死价格。

计数规则：

- 1 张照片：1 次
- 1 份手书：1 次
- 15 分钟以内录音：1 次
- 超过 15 分钟且不超过 30 分钟的录音：2 次

次数不因月底清零。取消月度方案后，已经发放但未使用的次数继续保留。

使用免费空间或媒体额度成功上传的内容随账号保留。删除媒体不返还额度。
注销账号按公开规则删除服务端数据。“请 DU 喝杯茶”收入不计入核心存储
单位经济。

## 整篇结算流程

付费触发点是整篇日迹或信件的最终提交，不是单个媒体选择或制作过程。

### 创作

1. 用户自由输入文字。
2. 用户可连续拍照、选图、录音和手书。
3. 媒体先写入加密临时目录。
4. 创作期间不弹付款窗口。

### 保存或寄出

用户点击 `保存日迹` 或 `寄出信件` 后，系统统一计算整篇内容：

```text
文字                         免费
照片 3 张                    3 次
录音 1 段 · 8 分钟          1 次
已有免费空间或额度可覆盖     1 次
本次还需要                   3 次
```

额度充足时直接保存。额度不足时展示可覆盖本次内容的最小商品，同时保留更大
次数包和月度方案入口。

结算页操作：

1. 购买最小可覆盖次数并保存
2. 购买更大次数包
3. 查看月度方案
4. 移除媒体并保存纯文字
5. 继续编辑

支付成功后自动返回同一编辑上下文并继续保存，不要求用户再次点击。

### 扣除时机

1. 商店完成购买。
2. 服务端验证订单并增加媒体额度。
3. 客户端加密媒体。
4. 附件上传成功并校验。
5. 结构化记录提交成功。
6. 服务端原子扣除本篇需要的额度。

任一步骤失败都不能重复扣款或生成重复记录。

## 草稿与异常恢复

- 用户取消支付：返回原编辑页，整篇内容保持可编辑。
- 网络或商店不可用：加密草稿保留 72 小时。
- App 崩溃或进程终止：下次启动恢复待保存草稿。
- 商店已扣款但服务端未确认：显示“付款已完成，正在确认”，禁止重复购买。
- 支付成功但上传失败：额度保留或处于预留状态，不最终扣除，自动重试。
- 用户选择纯文字保存：确认后移除本篇媒体并保存文字。
- 未来信只有在付款、上传、数据库写入和通知调度一致后才视为寄出。
- 草稿过期清理前提示一次；清理不得影响已经成功保存的内容。

临时稿不是免费本地媒体模式，不进入日迹或信箱，也不能作为正式内容长期使用。

## 支付渠道

### 商店支付

- iOS：StoreKit 2
- Google Play：Google Play Billing
- 中国大陆 Android 商店：使用对应商店允许的应用内支付方案

不在 iOS 或 Google Play 版本中使用支付宝、微信二维码或网页支付绕过商店
数字商品规则。

所有渠道通过统一 Billing Provider 接口接入。服务端统一保存：

```text
provider
product_id
transaction_id
account_id
status
granted_credits
expires_at
verified_at
```

客户端购买回调不能直接发放额度，必须完成服务端验单。购买权益绑定 DU 账号，
用户在其他平台登录同一账号后可以继续使用已获得的额度。

### 请 DU 喝杯茶

入口：

```text
我 → 关于 DU → 请 DU 喝杯茶
```

它使用可重复购买的消耗型应用内购买，不增加媒体空间或额度，不解锁功能，
不增加徽章或特权，未注册用户也能使用，不展示外部收款二维码。

建议文案：

```text
如果 DU 曾替你留住一些不想忘记的时刻，可以请开发者喝杯茶。
支持不会解锁功能，也不会增加空间，只用于支持后续维护。
```

## 付费说明文案

空间用完时只说明：

```text
照片与录音空间已用完
你仍然可以继续写纯文字记录。
```

开发者成本原因只放在完整方案页的套餐之后：

```text
为什么照片与录音需要付费

DU 由个人独立开发与维护。文字同步占用很少，会持续免费；照片、录音和
手书会长期产生存储、传输和备份费用。付费额度用于覆盖这些持续成本，
让这些记录在换设备后仍能回来。
```

不使用“服务器很贵”“开发者不容易”“求支持”“绝对安全”“永不丢失”或
“军用级加密”等表达。

## 数据与成本约束

- 录音从 WAV 改为 AAC/M4A，建议 48–64 kbps 单声道。
- 照片保存适合日记长期阅读的高质量压缩版本，不默认上传相机原始大图。
- 附件以内容哈希去重。
- 一次性额度净收入的一部分作为长期存储准备金。
- 监控平均照片大小、平均录音时长、每个注册用户存储成本、首次结算转化率、
  次数包复购率和月度方案取消率。
- 若录音时长或媒体均值显著高于设计假设，只调整未来新商品，不追溯削减用户
  已获得的额度。

## 合规与文案发布

账号和同步上线前必须同步更新：

- 应用内隐私政策与服务条款
- 公开 HTTPS 法律页面
- App Store 隐私标签
- Google Play 数据安全表
- 中国大陆商店隐私清单与 APP 备案材料
- 账号注销与服务端删除说明
- 应用内购买、自动续费、恢复购买和退款说明

开发环境、客户端占位 UI 或测试支付存在，不代表可宣称账号同步和换机恢复
已经上线。

## 分阶段实施

1. **媒体成本基础**：AAC/M4A、图片压缩、媒体大小统计与旧 WAV 兼容。
2. **账号和密钥**：注册、登录、令牌、设备身份、恢复凭证、注销。
3. **文字同步**：本地认领、增量同步、墓碑、冲突、重装恢复。
4. **媒体同步**：客户端加密、断点续传、哈希校验、孤儿清理。
5. **额度与结算**：500 MB 免费空间、整篇核算、额度账本、原子扣除。
6. **商店支付**：StoreKit 2、Play Billing、服务端验单和恢复购买。
7. **产品界面**：注册说明、账号页、整篇结算页、方案页、喝茶入口。
8. **合规和发布**：法律文本、商店声明、账号删除、生产环境与恢复演练。

不得跨过账号与同步验收，直接把收费 UI 接到尚不能可靠恢复的数据服务上。

## 验收门槛

- 未注册用户升级后仍可访问全部原本地数据。
- 注册和首次认领失败不破坏本机数据。
- 新设备登录后恢复全部结构化记录和已同步媒体。
- 两台设备离线编辑后重新联网不丢失、不重复。
- 删除墓碑在所有设备收敛。
- 服务端无法直接读取加密正文和附件。
- 正常换机可通过任一已绑定登录方式进入账号，并由可信旧设备批准；没有旧设备
  时恢复凭证路径可用。
- 整篇内容只出现一次结算，不逐个媒体付款。
- 纯文字路径始终可用。
- 取消支付、验单延迟、上传失败、进程终止和草稿过期均有恢复路径。
- 重复支付回调、退款、续费失败和跨平台登录不会重复发放额度。
- “请 DU 喝杯茶”不产生功能权益。
- 本地完整备份仍能独立导出和恢复。
- iOS、Google Play 与计划发布的国内 Android 渠道分别通过支付和隐私审核。

## Git 与 GitHub 历史策略

- 改动前基线使用带说明的标签 `pre-account-sync-2026-09-02`。
- 所有开发位于 `feat/account-sync-media-billing`。
- 每个实施阶段独立提交，禁止把全部功能压成一个提交。
- 不 amend 已推送提交，不 rebase 或 squash 已公开历史。
- 不使用 force push。
- 通过普通 Pull Request 合并，保留功能分支提交。
- 合并前创建候选标签；正式发布使用语义化版本标签和 GitHub Release。
- 数据库迁移只前进不回退；旧字段和旧媒体格式按兼容策略保留。
- 密钥、商店凭据、签名文件、真实用户数据或生产配置不得提交。
