# 渡 账号与加密同步实施方案

## 产品结论

渡应提供“可选账号 + 本地优先同步”，不应强制用户登录后才能写作。

- 未登录：全部功能可用，数据保存在本机，可手动导出和恢复。
- 登录后：本机仍是主要数据库，后台增量同步，离线可写。
- 新设备登录：下载并解密账号数据，恢复文字、信件、书、散页、照片、录音和头像。
- 隐私承诺：在登录、上传、下载、删除、冲突和换机恢复全部通过验收前，不宣称“数据跟账号走”。

这比“所有正规软件都必须强制账号”更合适。私人日记类产品强制登录会增加隐私风险和流失；专业标准是让用户明确选择同步，并且真的能恢复。

## 推荐技术路线

### 中国大陆首发

优先评估 LeanCloud 中国版作为第一版托管后端：

- 用户认证。
- 云端结构化数据。
- 文件对象存储。
- 云函数或服务端校验。
- 中国大陆网络可达性。

采用前必须在其当前控制台确认个人主体、APP 备案、域名、价格、数据地域、账号注销和导出能力。若个人主体或成本不满足，则改用中国大陆云厂商的 Serverless API + 托管数据库 + 对象存储，不应临时切换到大陆访问不稳定的海外免费服务。

### 非大陆验证版

Supabase 等海外托管服务适合低成本验证，但不作为中国大陆正式同步的默认方案。原因是网络可达性、数据跨境和备案链路都可能阻塞大陆商店上架。

## 客户端架构

继续使用 WatermelonDB，不把页面改成“每次打开都请求服务器”。

```text
React Native UI
      |
WatermelonDB 本地事务
      |
Sync Coordinator
  |          |
Outbox      Pull Cursor
  |          |
HTTPS Sync API
  |          |
结构化数据   加密附件对象存储
```

WatermelonDB 自带记录变更状态，可接入 `synchronize()`。服务端必须实现 pull/push 协议、幂等写入和删除墓碑，不能用整库 JSON 覆盖。

## 账号设计

第一版支持：

1. 邮箱 + 验证码或安全密码。
2. iOS 可追加“通过 Apple 登录”。
3. Android 后续按发布地区追加平台登录。

手机号验证码不是首选：它有持续短信成本、实名和反滥用要求。只做第三方登录也不合适，因为中国大陆 Android 不能依赖 Google 登录。

账号表至少包含：

```text
account_id
email_hash
status
created_at
updated_at
deletion_requested_at
```

认证令牌只保存在 Keychain/Android Keystore，不写入 AsyncStorage、日志或备份文件。

## 数据模型

每个可同步实体都要有：

```text
id                 客户端生成的全局唯一 ID
account_id         云端所有者
revision           服务端单调递增版本
created_at
updated_at
deleted_at         删除墓碑
device_id
```

当前已有的记录 ID 保持不变。登录后将本地匿名数据一次性认领到账号，不能重新生成 ID，否则信件、回信、书页、散页和节点关系会断裂。

同步范围：

- 用户资料与设置。
- 日迹和附件。
- 未来信、到达状态与回信。
- 念想、便利贴。
- 副本、节点、连接和便利贴。
- 书、书页、散页。
- 头像、封面、照片、手书和录音。

静态标签和应用内置范例模板不上传；用户实际保留或修改后的普通记录按用户数据同步。

## 加密设计

渡保存的是高敏感私人内容，推荐客户端加密后再上传：

1. 每个账号在设备端生成 256 位主密钥。
2. 文字字段和附件使用 AES-256-GCM，每个对象使用独立随机 nonce。
3. 主密钥由恢复密钥派生的密钥包装后保存到服务器。
4. 设备本地副本保存在 Keychain/Android Keystore。
5. 服务端只保存密文、必要同步元数据和校验值。

必须明确代价：真正端到端加密后，运营方无法替用户找回明文。用户忘记密码且丢失恢复密钥时，不能承诺后台人工恢复。产品需要在开通同步时生成恢复密钥，并要求用户确认已保存。

## 同步规则

### 上传

- 本地事务成功后立即进入待同步状态。
- 网络可用时按批次推送。
- 每批携带幂等请求 ID，重试不得创建重复记录。
- 附件先加密上传，确认对象存在后再提交引用。

### 下载

- 每个账号保存服务端游标。
- 只拉取游标之后的变更。
- 在一个 WatermelonDB 写事务中应用批次。
- 拉取失败不影响本地继续写作。

### 冲突

- 日迹正文、用户资料：同一字段最后修改者生效，同时保留冲突副本供恢复。
- 信件到达/拆封：状态只能按 `traveling → arrived → opened` 前进。
- 删除：删除墓碑优先于更早版本的编辑。
- 书页、节点和散页：按实体合并，不整本覆盖。
- 附件：按内容哈希去重，不用文件名判断相同。

### 删除

- 本地删除立即隐藏并上传墓碑。
- 墓碑保留有限时间，防止离线旧设备把数据重新上传。
- 账号注销进入冻结期，随后删除结构化数据、附件、备份和认证账号。
- 应用内提供可见的注销进度和最终完成状态。

## 本地匿名数据迁移

用户首次登录时：

1. 创建本地加密救援备份。
2. 统计本地记录与附件，展示将同步的范围。
3. 将当前匿名身份绑定为该账号的首个设备身份。
4. 保持所有记录 ID，不修改关系字段。
5. 分批加密上传，记录进度。
6. 服务端确认完整后写入迁移完成标记。
7. 任何阶段失败都保留本地原数据，可继续重试。

同一账号已有云数据时，先下载再按实体合并，不能询问用户选择“覆盖本机”或“覆盖云端”作为默认方案。

## 分阶段交付

### 阶段 0：基础决策

- 固定正式包名、域名和发布地区。
- 确认云服务个人主体与费用。
- 完成威胁模型、数据清单和隐私政策草稿。
- 创建开发/生产隔离环境。

### 阶段 1：账号与文字同步

- 注册、登录、退出、令牌刷新和注销。
- 本地匿名数据认领。
- 只同步结构化文字数据。
- 飞行模式写入、多设备编辑、删除和重装恢复通过自动测试。

### 阶段 2：媒体同步

- 照片、录音、手书、头像和封面客户端加密上传。
- 断点续传、哈希去重、孤儿文件回收。
- 弱网、后台中断和存储不足测试。

### 阶段 3：恢复与正式发布

- 恢复密钥流程。
- 新设备全量恢复。
- 账号注销和服务端清除证明。
- 更新应用内隐私文案、App Store 隐私标签和 Google Play 数据安全。
- 完成中国大陆 APP 备案与商店隐私检查。

## 上线验收门槛

必须全部通过：

- 两台设备离线编辑后重新联网，不丢记录、不产生重复。
- 删除在所有设备收敛，旧设备不能复活已删内容。
- 卸载重装后仅凭账号和恢复密钥恢复完整数据。
- 照片、录音、手书和封面可打开且哈希一致。
- 账号注销后认证、数据库、对象存储和备份均不可再访问。
- 服务端无法直接读取端到端加密正文和附件。
- 本地备份仍可独立恢复，不把云同步变成唯一逃生路径。

## 当前状态

当前版本仍是本地优先、无账号同步。已有完整本地备份、校验、恢复和失败回滚，这些能力应保留。下一步不是修改宣传文案，而是先完成阶段 0 并创建真实云端开发环境；在阶段 3 验收前，应用内继续明确提示“尚未提供账号同步”。
