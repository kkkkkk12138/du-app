# 渡 中国大陆 Android 应用商店上架指导书

适用版本：1.0.1（`versionCode 2`）

更新日期：2026-08-07

适用对象：以中国大陆个人开发者身份免费发布“渡”。本文件不代表每家商店在所有日期、类目都接受个人主体。厂商规则会变，提交当天必须以各开放平台控制台列出的材料为准。

当前发布策略：免费下载、无广告、无应用内购买、无账号登录、无云同步。以后增加收费能力时另做版本开发和合规申报，不在首发资料中提前宣传。

## 先理解发布体系

中国大陆没有一个覆盖全部 Android 设备的统一商店。Google Play 的应用条目、AAB、测试和审核不能自动同步到华为、小米、OPPO、vivo、荣耀或应用宝。每个平台都要分别完成开发者认证、应用建档、APK 上传、隐私检查和审核。

当前首发顺序：

1. 完成 APP 备案和软件著作权申请。
2. 用正式 Release APK 完成 Android 真机回归和商店截图。
3. 先投接受个人主体且材料要求已满足的平台。
4. 再投需要补充资质或规则更严格的平台。
5. 每个商店保留独立的账号、应用 ID、审核记录和版本发布记录。

iOS 发布可以并行准备。若 APP 备案尚未获批，iOS 首发地区不选择中国大陆，备案完成后再增加中国大陆销售地区。

## 个人主体的现实限制

- “渡”属于私人记录/生活方式工具，不涉及游戏、新闻、医疗、金融、教育培训或公开社交，通常不需要这些特殊行业许可证。
- APP 备案允许个人作为主办者，但接入商、云服务商和商店可能有各自的身份核验流程。
- 某些商店、类目或商业能力可能只接受企业主体。若控制台明确拒绝个人主体，不能借用他人公司或购买套壳资质；应跳过该渠道，或以后依法设立主体再申请。
- 软件著作权并非所有普通工具在法律上的统一上架前置条件，但部分商店或审核情形会要求。为减少反复，建议以本人作为著作权人申请“渡”的计算机软件著作权。

## 第二阶段：准备基础资质

### 1. 域名与中国大陆服务器

当前 1.0.1 没有账号同步、自建业务服务器或用户内容上传接口。公开政策暂由 `du-legal` GitHub Pages 托管，四个页面已匿名验证可访问。

接入商若明确要求本人域名或中国大陆网络资源，再按以下顺序处理：

1. 用本人实名信息购买长期持有的域名。
2. 选择支持个人备案的中国大陆云服务商。
3. 完成域名 ICP 备案。
4. 将隐私政策、服务条款和支持页面迁移到备案域名。
5. 云数据库、对象存储、日志和备份选择中国大陆地域，避免在没有评估的情况下把私人日记跨境传输。

不要为取得备案而虚构域名、IP、服务器或云服务。纯本地版本是否需要补充网络资源，由接入服务商和提交平台按实际业务形态判定。

### 2. APP 备案

APP 备案通常通过网络接入服务商、云服务商或分发平台提交，而不是只在应用商店填写一个号码。

准备：

- 个人身份证明与真实联系方式。
- 应用名称、包名、签名证书指纹和运行平台。
- 域名及其 ICP 备案信息。
- 应用图标、功能说明和服务内容。
- 隐私政策 URL。

从接入商提交后，按要求完成短信核验；取得备案号后，在应用内“关于渡”和隐私政策页面按要求展示。官方入口：`https://beian.miit.gov.cn/`

### 3. 软件著作权

建议准备：

- 本人身份证明。
- 软件名称和版本号。
- 源程序鉴别材料。
- 用户手册或设计说明书。
- 权利归属说明。

优先走中国版权保护中心官方渠道：`https://www.ccopyright.com.cn/`。不要把完整私有仓库、签名密钥或云端密钥交给不可信代办。

## 第三阶段：完成合规自检

正式包必须满足：

- 首次启动先展示隐私政策摘要，用户同意前不初始化非必要 SDK、不申请权限、不联网上传个人信息。
- 相机、麦克风、定位、通知、照片选择分别在功能触发时申请，并解释用途。
- 隐私政策逐项列出文字、照片、录音、手书、定位、头像、账号标识的处理目的、方式、保存期限和删除方式。
- 当前版本没有账号，因此不存在服务端账号注销；后台问卷和审核说明必须如实写明。
- 提供内容删除、数据导出和恢复。
- 第三方 SDK 清单与最终 APK 实际依赖一致。
- 不声明未实现的自动云同步、加密或数据恢复能力。

以后增加账号同步后，必须先重做服务端安全、账号注销、数据跨境和隐私评估，再重写：

```text
docs/app-store/PRIVACY_POLICY.md
docs/google-play/DATA_SAFETY.md
src/features/profile/LegalDocumentScreen.tsx
```

每家平台重复执行：

1. 注册并完成个人实名认证。
2. 确认当前类目接受个人主体。
3. 创建应用，包名必须与 APK 一致。

5. 上传同一签名的 Release APK。
6. 填写权限用途、隐私采集、第三方 SDK 和账号注销路径。
7. 提交审核，逐条保存驳回原因和修复版本。
8. 审核通过后按平台能力选择分阶段发布，再检查安装、启动、更新和通知。

不要为每家商店创建不同业务代码。确有渠道标识需求时只使用构建参数，并保证功能、隐私行为和签名一致。

## 费用判断

- 首发把 App 价格设置为免费，不接广告、不接支付 SDK、不创建订阅或应用内购买。
- 多数大陆厂商开发者账号注册通常不采用 Google Play 的一次性注册费模式，但是否收费、是否接受个人主体，以本人注册页面和协议为准。
- APP 备案本身不应理解为“买一个备案号”，但域名、中国大陆服务器、短信、对象存储、数据库和带宽会产生持续费用。
- 软件著作权走官方流程与委托代理的费用不同；代理费不是法定上架费。
- 若未来通过 IAP 或订阅收费，还要分别接入商店支付、签署分成协议并处理税务信息。

## 本人必须完成的操作

以下步骤涉及法定身份、短信、人脸、签署或账号协议，不能由代码仓库代办：

1. 在接入商完成 APP 备案实名认证、人脸和短信核验。
2. 在中国版权保护中心完成实名认证、签章和软著提交。
3. 在每家厂商平台注册个人开发者并接受平台协议。
4. 核对控制台是否接受个人主体和当前类目。
5. 提交备案号、软著证书及平台临时新增的身份证明材料。
6. 在发布前确认上架地区、发布时间和最终商店文案。

身份证照片、住址、验证码、人脸材料、账号密码和签名密钥不得放入 GitHub。
