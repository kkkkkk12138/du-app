# 渡 中国大陆 Android 应用商店上架指导书

适用对象：以中国大陆个人开发者身份发布“渡”。本文件是执行清单，不代表每家商店在所有日期、类目都接受个人主体。厂商规则会变，提交当天必须以各开放平台控制台列出的材料为准。

## 先理解发布体系

中国大陆没有一个覆盖全部 Android 设备的统一商店。Google Play 的应用条目、AAB、测试和审核不能自动同步到华为、小米、OPPO、vivo、荣耀或应用宝。每个平台都要分别完成开发者认证、应用建档、APK 上传、隐私检查和审核。

首发建议按以下顺序：

1. 先完成 Google Play 与 iOS，验证产品稳定性。
2. 确定是否立即提供账号云同步。提供网络服务后，域名、服务器、隐私政策和 APP 备案必须作为同一套基础设施规划。
3. 完成 APP 备案和软件著作权准备。
4. 先投华为、小米、OPPO、vivo、荣耀，再按需要投应用宝。
5. 每个商店保留独立的账号、应用 ID、审核记录和版本发布记录。

## 个人主体的现实限制

- “渡”属于私人记录/生活方式工具，不涉及游戏、新闻、医疗、金融、教育培训或公开社交，通常不需要这些特殊行业许可证。
- APP 备案允许个人作为主办者，但接入商、云服务商和商店可能有各自的身份核验流程。
- 某些商店、类目或商业能力可能只接受企业主体。若控制台明确拒绝个人主体，不能借用他人公司或购买套壳资质；应跳过该渠道，或以后依法设立主体再申请。
- 软件著作权并非所有普通工具在法律上的统一上架前置条件，但部分商店或审核情形会要求。为减少反复，建议以本人作为著作权人申请“渡”的计算机软件著作权。

## 第一阶段：固定不可随意更改的信息

在任何商店建档前确认：

```text
应用中文名：渡
Android applicationId：待最终确认，当前为 com.duapp
开发者主体：本人法定姓名
著作权人：应与开发者主体一致
隐私政策主体：应与开发者主体一致
支持邮箱：待填写
官方网站/隐私政策域名：待购买和备案
```

包名首次发布后不应更换。APP 备案、软著、隐私政策和各商店后台中的应用名、包名、主体必须尽量一致。

## 第二阶段：准备基础资质

### 1. 域名与中国大陆服务器

账号同步若面向中国大陆用户，优先选择中国大陆地域的合规云服务：

1. 用本人实名信息购买长期持有的域名。
2. 选择支持个人备案的中国大陆云服务商。
3. 完成域名 ICP 备案。
4. 部署公开可访问的隐私政策、服务条款、账号注销说明和支持页面。
5. 云数据库、对象存储、日志和备份选择中国大陆地域，避免在没有评估的情况下把私人日记跨境传输。

纯本地版本也不能因此自动跳过商店的隐私和备案检查；以接入服务商与提交平台的实际判定为准。

### 2. APP 备案

APP 备案通常通过网络接入服务商、云服务商或分发平台提交，而不是只在应用商店填写一个号码。

准备：

- 个人身份证明与真实联系方式。
- 应用名称、包名、签名证书指纹和运行平台。
- 域名及其 ICP 备案信息。
- 应用图标、功能说明和服务内容。
- 隐私政策 URL。

从接入商提交后，按要求完成短信核验；取得备案号后，在应用内“关于渡”和隐私政策页面按要求展示。官方入口：`https://beian.miit.gov.cn/`

### 3. 软件著作权

建议准备：

- 本人身份证明。
- 软件名称和版本号。
- 源程序鉴别材料。
- 用户手册或设计说明书。
- 权利归属说明。

优先走中国版权保护中心官方渠道：`https://www.ccopyright.com.cn/`。不要把完整私有仓库、签名密钥或云端密钥交给不可信代办。

## 第三阶段：完成合规自检

正式包必须满足：

- 首次启动先展示隐私政策摘要，用户同意前不初始化非必要 SDK、不申请权限、不联网上传个人信息。
- 相机、麦克风、定位、通知、照片选择分别在功能触发时申请，并解释用途。
- 隐私政策逐项列出文字、照片、录音、手书、定位、头像、账号标识的处理目的、方式、保存期限和删除方式。
- 提供应用内账号注销入口；注销不能只要求发邮件。
- 提供内容删除、账号删除、数据导出和恢复。
- 第三方 SDK 清单与最终 APK 实际依赖一致。
- 不声明未实现的自动云同步、加密或数据恢复能力。

增加账号同步后，必须重写：

```text
docs/app-store/PRIVACY_POLICY.md
docs/google-play/DATA_SAFETY.md
src/features/profile/LegalDocumentScreen.tsx
```

## 第四阶段：准备大陆商店 APK

大陆厂商商店通常接收签名 APK，而不是 Google Play AAB。当前产物：

```text
android/app/build/outputs/apk/release/app-release.apk
```

提交前：

1. 固定正式 `applicationId`、`versionCode` 和 `versionName`。
2. 使用与后续更新完全相同的生产签名。
3. 在 Android 真机上安装 Release APK，完成完整回归。
4. 使用厂商隐私检测和 APK 安全扫描工具检查。
5. 不把 APK、JKS、密码或 `keystore.properties` 提交到 GitHub。

## 第五阶段：逐商店提交

建议建立以下平台账号并逐个核对“个人开发者”和“生活方式/实用工具”类目的最新要求：

| 渠道 | 开放平台 |
| --- | --- |
| 华为 AppGallery | `https://developer.huawei.com/consumer/cn/` |
| 小米应用商店 | `https://dev.mi.com/` |
| OPPO 软件商店 | `https://open.oppomobile.com/` |
| vivo 应用商店 | `https://dev.vivo.com.cn/` |
| 荣耀应用市场 | `https://developer.honor.com/cn/` |
| 腾讯应用宝 | `https://open.tencent.com/` |

每家平台重复执行：

1. 注册并完成个人实名认证。
2. 确认当前类目接受个人主体。
3. 创建应用，包名必须与 APK 一致。
4. 上传图标、截图、介绍、隐私政策 URL、备案信息和所需资质。
5. 上传同一签名的 Release APK。
6. 填写权限用途、隐私采集、第三方 SDK 和账号注销路径。
7. 提交审核，逐条保存驳回原因和修复版本。
8. 审核通过后先小范围发布，再检查安装、启动、更新和通知。

不要为每家商店创建不同业务代码。确有渠道标识需求时只使用构建参数，并保证功能、隐私行为和签名一致。

## 费用判断

- 多数大陆厂商开发者账号注册本身通常不以 Google Play 的一次性注册费模式收费，但实名认证、规则和类目限制以当日控制台为准。
- APP 备案本身不应理解为“买一个备案号”，但域名、中国大陆服务器、短信、对象存储、数据库和带宽会产生持续费用。
- 软件著作权走官方流程与委托代理的费用不同；代理费不是法定上架费。
- 若未来通过 IAP 或订阅收费，还要分别接入商店支付、签署分成协议并处理税务信息。

## 当前项目还缺什么

在提交中国大陆商店前仍需完成：

1. 固定正式包名。
2. 准备正式应用图标、功能图和 Android 截图。
3. 购买域名并发布隐私政策、服务条款、支持和注销页面。
4. 决定中国大陆账号同步云服务并完成数据合规设计。
5. 完成 APP 备案。
6. 申请软件著作权。
7. 用至少一台主流 Android 真机完成 Release 验收。
8. 逐平台确认个人主体是否接受当前类目。

在这些事项完成前，现有 APK 可以用于模拟器和真机测试，但不应把“能构建”误认为“已具备大陆全渠道上架资格”。
